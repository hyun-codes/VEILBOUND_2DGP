# 플레이어 스프라이트와 애니메이션 정보

## 파일

- [Red_Hand_Jack_SPRITESHEET.png](Red_Hand_Jack_SPRITESHEET.png): 사용자가 제공한 원본 시트. 이미지를 수정하지 않았다.
- [animations.json](animations.json): VEILBOUND에서 사용할 프레임과 재생 설정. `veilbound-grid-animations` 버전 1이라는 프로젝트 자체 형식이며 Aseprite 내보내기 형식이나 Tiled TSJ가 아니다.
- [전체 스프라이트 분류표](../../../docs/player_sprite_inventory.md): Jack1~139의 액션과 무기 유무를 확인한 기록.

2026-11-06에 game/player.py의 AnimationSet·Player가 이 JSON을 읽도록 연결했다. 기본 활성 모션 5개만 물리 상태에 맞춰 재생하고 좌우 반전과 발 앵커를 적용한다. 선택 모션 3개와 사망 모션은 사용하지 않는다. 이미지와 JSON 자체는 이번 구현에서 변경하지 않았다.

## 이미지와 격자

원본 이미지는 640×1664px, 셀은 64×64px, 격자는 10열×26행이다. margin과 spacing은 0이다. 모든 행에 10개 동작 프레임이 있는 것은 아니므로 빈 셀까지 재생하지 않는다. 현재 업로드 이미지가 이전에 검사한 시트·개별 PNG와 동일한지 확인했다.

JSON의 `row`와 `columns`는 **좌상단 원점, 0부터 시작하는 인덱스**다. 예를 들어 `idle.row=0`, `idle.columns=[0,1,2]`는 첫 행의 세 프레임을 뜻한다.

`source_frame_numbers`는 외부 개별 이미지의 Jack 번호를 기록한 추적용 정보다. 게임에서 Jack PNG를 별도로 읽으라는 뜻도, 시트의 일렬 인덱스라는 뜻도 아니다. 특히 Jack15는 4번째 행 첫 셀이지 시트의 15번째 셀이 아니다. 시트의 빈 셀 때문에 번호를 `Jack번호 - 1`로 계산하면 잘못된 모션을 재생한다.

| --- | --- | --- | --- | --- | --- | --- |
| `idle` | 1~3 | 0 | 3 | 예 | 예 | 240ms |
| `run` | 15~22 | 3 | 8 | 예 | 예 | 80ms |

| `fall` | 28~31 | 5 | 4 | 예 | 예 | 100ms |
| `land` | 32~35 | 6 | 4 | 아니오 | 예 | 40ms |
| `coin_flip` | 4~11 | 1 | 8 | 아니오 | 아니오 | 100ms |
| `run_transition` | 12~14 | 2 | 3 | 아니오 | 아니오 | 50ms |
| `hurt` | 114~116 | 20 | 3 | 아니오 | 아니오 | 60ms |

**위 시간은 원본 제작자의 재생 속도가 아닌 테스트용 초기값이다.** 원본 설명 텍스트에는 FPS나 프레임별 시간이 없다. 그래서 JSON에 `timing_status=initial_tuning_values_not_source_timings`를 명시했다. 움직임과 연결을 직접 재생해 본 뒤 조정한다.

`enabled=true`인 5개만 기본 재생 목록에 등록한다. 나머지 3개는 프레임 위치를 확인해 둔 선택 모션이며, `enabled=false`인 동안 자동 선택하지 않는다. `hurt`를 켜더라도 체력이나 생존 피격 시스템을 추가한다는 뜻은 아니다. 이동 전환의 재생 방향도 구현 전에 검증한다.

## pico2d에서 사용할 좌표

JSON의 프레임 `row=r`, `column=c`에 대해 원본 PNG 좌상단 기준 사각형은 다음과 같다.

```text
x = c * 64
y_top = r * 64
width = 64
height = 64
```

pico2d의 아래쪽 원점 자르기 좌표로 바꿀 때는 다음 식을 사용한다.

```text
x = c * 64
y_bottom = 1664 - (r + 1) * 64
```

예를 들어 idle 첫 프레임의 자르기 사각형은 `(0, 1600, 64, 64)`, run 첫 프레임은 `(0, 1408, 64, 64)`다. 이 식은 원본 이미지 좌표에만 적용한다. 이후 맵 좌표·카메라 위치·3배 확대를 그리기 단계에서 적용하며 원본 프레임 크기를 미리 192×192로 저장하지 않는다.

## 발 기준점과 동작 연결

공통 앵커의 초기값은 셀 좌상단 기준 `(32,44)`다. 무기 없는 대기 이미지의 발 아래 경계와 셀 중심선을 바탕으로 정했다. 발 위치가 `(world_x, world_y)`일 때 앵커를 그곳에 맞추어 모든 모션에 같은 기준을 적용한다. 그림의 투명 부분을 프레임마다 자동으로 잘라 크기를 바꾸면 캐릭터가 들썩일 수 있으므로 64×64 셀을 유지한다.

`source_facing=right`는 검사한 원본의 기본 방향이다. 좌우 반전 시 같은 발 기준점을 유지한다. 이 앵커와 방향은 게임 화면에서 연결·반전 검증을 마친 값이 아니므로 실제 배치에서 재확인한다. 대기의 실제 몸체 높이는 약 15~16px이며 **64×64 셀 전체를 충돌체로 사용하지 않는다.** 충돌체는 게임 코드에서 별도 정의한다.

물리 상태가 애니메이션을 선택한다. jump_start 5프레임이 끝날 때까지 점프 판정을 미루거나, land가 끝날 때까지 다음 이동·점프를 막지 않는다. 공중 상태가 바뀌면 재생 도중에도 해당 상태의 모션으로 전환한다. 반복하지 않는 클립은 완료 후 마지막 프레임을 유지하는 것을 기본으로 하되 실제 상태 전환이 우선한다. 키를 누르고 있다는 이유로 매 프레임 같은 애니메이션을 처음부터 재시작하지 않는다. 프레임 재생은 실제 경과 시간으로 계산한다.

## 무기와 사망 모션

VEILBOUND는 무기를 사용하지 않는다. 낫 소환·무장 이동·공격·조준·총 발사 모션은 JSON 재생 목록에 없다. 원본 시트 안에 해당 그림이 존재해도 게임 기능으로 사용하지 않는다. 설명에 unarmed가 붙은 총 모션도 제외했다.

`death`는 `animations`에 등록하지 않고 `unavailable_animations.death`에 미준비 상태만 기록했다. Jack117~118은 낫 형태가 있고, Jack119~121은 무기 형상은 없지만 입자와 연결 문제를 검증해야 한다. 사망 구현에서 빠진 death를 무장 모션이나 무작위 프레임으로 대체하지 않는다. 무기 없는 사망 모션을 확정한 뒤 명시적으로 등록한다.
