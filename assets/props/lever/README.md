# 톱니 레버 에셋

2026-11-07 사용자 요청으로 Castle Tileset 소품 시트에서 **위쪽의 내부가 채워진 톱니 레버**만 추출했다. 문·철창·상자·아래쪽 빈 톱니 레버는 포함하지 않았다. 새 그림을 생성하거나 원본 픽셀·색·알파·크기를 수정하지 않고 세 영역을 잘라 한 줄로 배치했다.

## 파일과 프레임

- [lever.png](lever.png): 192×32px RGBA, 64×32 셀3개, margin/spacing=0.
- [animations.json](animations.json): 프로젝트 자체 veilbound-grid-animations 버전1의 소품 메타데이터. Stage 3의 공유 TSJ 정적 배치에 연결했으며, 전환 클립의 실행 재생은 아직 연결하지 않았다.

| 열 인덱스 | 원본 자세 | 프로젝트 용도 |
| --- | --- | --- |
| 0 | 손잡이 왼쪽 | inactive 정지 상태 |
| 1 | 손잡이 위쪽 | 전환 중간 자세 |
| 2 | 손잡이 오른쪽 | active 정지 상태 |

inactive/active는 프로젝트에서 붙인 이름이며 제작자가 지정한 전원·문 상태라는 뜻은 아니다. activate는0→1→2, deactivate는2→1→0, 모두 비반복이다. 정지 클립은 각각 한 프레임이다. 프레임당80ms는 검토용 초기값으로 원본 제작자의 재생 시간이나 실제 플레이로 검증한 값이 아니다. 실제 레버 입력·문 연결·상태 확정 시점은 아직 구현하지 않았다.

## 추출 좌표와 기준점

입력은 사용자가 제공한 caslePropsSheet.png(3456×384px)다. 원본 좌상단 기준 `(x,y,width,height)`는 순서대로 `(256,192,64,32)`, `(640,192,64,32)`, `(1024,192,64,32)`다. 출처 파일명·크기·SHA256과 세 좌표를 JSON의 provenance에 기록했다. 사용자의 임시 원본 파일은 변경하지 않았고, 다른 소품이 포함된 전체 원본은 이 폴더에 복제하지 않았다.

출력 시트는 좌상단0 기반으로 `(column*64,0,64,32)`를 자른다. 한 줄 시트이므로 pico2d 아래쪽 원점에서도 같은 사각형이다. 밑부분 기준점은 셀 내부 `(24,32)`로 두었다. 세 자세의 하단8행이 픽셀 단위로 동일해 톱니 바닥의 위치가 유지됨을 확인했다. 셀마다 투명 여백을 개별 제거하여 중심이 흔들리게 만들지 않는다.

64×32는 투명 여백을 포함한 셀 크기다. 실제 그림 경계는 왼쪽39×22px, 위쪽30×29px, 오른쪽39×22px로 자세마다 다르다. 기존 플레이어 몸 높이 약15px와 비교하면 큰 장치다. PNG 자체에는 확대·축소·팔레트 보정을 하지 않았다. 이후 Stage 3에서는 Tiled 오브젝트만0.5배(32×16 셀)로 배치했으며 최종 표시 크기·조작 범위는 실제 상호작용 연결과 사람의 평가 시 조정한다. 기존 player.AnimationSet은 플레이어 전용 필수 모션을 요구하므로 이 JSON을 그대로 넘기지 않는다.

## 검증 상태

원본/출력 PNG 크기·SHA256, 세 프레임 RGBA 완전 일치·구분 가능성·비어 있지 않음·하단 정렬, JSON 경로·격자·모든 클립 범위를 확인했다. 확대 이미지에서 위쪽 레버3자세만 포함됨을 시각 검사했다. 2026-11-07 Stage 3의 정적 Tiled 배치에 첫 자세를 연결했다. 표시 셀32×16, 좌하단(332,247), 받침(344,247)이며 원본 PNG는 그대로다. 게임 내 전환 재생·E 조작·문 연결·사람의 조작감은 아직 확인하지 않았다. 에셋 추출 단계에서는 게임 코드를 변경하지 않았다. 이후의 정적 맵 배치도 승인 전 재설계안 전체를 구현한 것은 아니다.
