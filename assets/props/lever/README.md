# 톱니 레버 에셋

2026-11-07 사용자 요청으로 Castle Tileset 소품 시트에서 **위쪽의 내부가 채워진 톱니 레버**만 추출했다. 문·철창·상자·아래쪽 빈 톱니 레버는 포함하지 않았다. 새 그림을 생성하거나 원본 픽셀·색·알파·크기를 수정하지 않고 세 영역을 잘라 한 줄로 배치했다.

## 파일과 프레임

- [lever.png](lever.png): 192×32px RGBA, 64×32 셀3개, margin/spacing=0.
- [animations.json](animations.json): 프로젝트 자체 veilbound-grid-animations 버전1의 소품 메타데이터. Stage 3의 공유 TSJ 배치와 game/lever_gate.py의 실제 레버 재생에 연결했다.

| 열 인덱스 | 원본 자세 | 프로젝트 용도 |
| --- | --- | --- |
| 0 | 손잡이 왼쪽 | inactive 정지 상태 |
| 1 | 손잡이 위쪽 | 전환 중간 자세 |
| 2 | 손잡이 오른쪽 | active 정지 상태 |

inactive/active는 프로젝트에서 붙인 이름이며 제작자가 지정한 전원·문 상태라는 뜻은 아니다. activate는0→1→2, deactivate는2→1→0, 모두 비반복이다. 정지 클립은 각각 한 프레임이다. 프레임당80ms는 검토용 초기값으로 원본 제작자의 재생 시간이나 실제 플레이로 검증한 값이 아니다. 2026-11-07 현실·착지·근접 상태의 E로 activate를 재생하고 연결된 차단문을0.4초 동안 올리는 기능을 구현했다. 열린 뒤에는 유지되며 deactivate는 현재 게임 입력으로 사용하지 않는다. R·추락은 초기 자세로 복구한다.

## 추출 좌표와 기준점

입력은 사용자가 제공한 caslePropsSheet.png(3456×384px)다. 원본 좌상단 기준 `(x,y,width,height)`는 순서대로 `(256,192,64,32)`, `(640,192,64,32)`, `(1024,192,64,32)`다. 출처 파일명·크기·SHA256과 세 좌표를 JSON의 provenance에 기록했다. 사용자의 임시 원본 파일은 변경하지 않았고, 다른 소품이 포함된 전체 원본은 이 폴더에 복제하지 않았다.

출력 시트는 좌상단0 기반으로 `(column*64,0,64,32)`를 자른다. 한 줄 시트이므로 pico2d 아래쪽 원점에서도 같은 사각형이다. 밑부분 기준점은 셀 내부 `(24,32)`로 두었다. 세 자세의 하단8행이 픽셀 단위로 동일해 톱니 바닥의 위치가 유지됨을 확인했다. 셀마다 투명 여백을 개별 제거하여 중심이 흔들리게 만들지 않는다.

64×32는 투명 여백을 포함한 셀 크기다. 실제 그림 경계는 왼쪽39×22px, 위쪽30×29px, 오른쪽39×22px로 자세마다 다르다. 기존 플레이어 몸 높이 약15px와 비교하면 큰 장치다. PNG 자체에는 확대·축소·팔레트 보정을 하지 않았다. 이후 Stage 3에서는 Tiled 오브젝트만0.5배(32×16 셀)로 배치했으며 현재 조작 범위는 받침(344,247) 기준 수평6px·발 높이 오차6px이며 사람의 평가 후 조정할 수 있다. 기존 player.AnimationSet은 플레이어 전용 필수 모션을 요구하므로 이 JSON을 그대로 넘기지 않는다.

## 검증 상태

원본/출력 PNG 크기·SHA256, 세 프레임 RGBA 완전 일치·구분 가능성·비어 있지 않음·하단 정렬, JSON 경로·격자·클립 범위를 확인했다. Stage 3에서는 손잡이 좌→위→우, 난간 이미지로 만든 차단문의 상승과 충돌 동기화, 케이블·문틀·상태 안내를 연결했다. 실제 SDL 키 입력으로 레버 작동·문 통과·클리어·재시작을 확인했다. 자동 검사93개에는 조작 조건·키 유지·포커스·중간/완료 상태·세계/조명 변경 후 유지·R/추락 복귀가 포함된다. 사람이 직접 조작한 감각·가독성 평가는 아직이다.

레버는 기존 A 조작점과 별도 장치이며 E 입력은 가장 가까운 유효 조작점 하나에만 전달한다. 차단문은 두 세계에서 같은 물리 장애물이고, 레버는 현실에서만 조작한다. 이번 연결은 레버·차단문 기능이며 두 조명을 같은 규칙으로 통일하는 전체 퍼즐 재설계는 아직 구현하지 않았다.
