# Stage 3: 위험한 골목 — 돌아오는 회로

상태: Tiled 맵·실행 가능한 정적 퍼즐 초안. 사람의 재미·난도 검증 전이다. 걷기 모션 개선은 보류했다. 이번 작업은 두 가로등과 세계별 길의 순서를 검사하며, 동물·몬스터 순찰과 접촉 판정은 아직 없다. EncounterPlan 오브젝트는 향후 쥐→지상 임프 배치 후보일 뿐 실행되는 적이 아니다.

출구는 시작점 바로 위 왼쪽 지붕에 보이지만96px 높아서 직접 뛸 수 없다. 오른쪽 아래로 건너가 A로 계단을 만든 후 위로 올라가, 상층의 서로 다른 세계 길을 거슬러 왼쪽 출구로 돌아온다. 새 규칙·열쇠·제한 시간 대신 Stage 2의 A/B·Shift를 재조합한다. 제어반은 공통 지면에 두어 잘못 조작한 뒤 그 자리에서 되돌릴 수 있게 했다.

## 알고리즘 검증의 의미

[tools/solve_stage3.py](../../tools/solve_stage3.py)는 표준 라이브러리deque의 BFS를 사용한다. 상태는 `(안전 지점, 현실/그림자, A배치, B빛)`이며 이동·점프,Shift,E를 간선으로 삼는다. Objects의 PuzzleNode15개·양방향 PuzzleLink14개는 검증 후보 지점/연결이다. 연결을 적었다고 통과 가능으로 가정하지 않고 실제 game/player.py의 속도·중력·몸체·collision을 사용해 걷기·점프 출발 위치를 시험한다. 지지 바닥·몸체 내부 겹침을 검사해 안정적으로 서 있을 수 있는 상태만 노드에 포함한다.

[solution.json](solution.json)은 현재 맵 SHA256, 탐색 범위와 찾은 경로를 담는다. 현재 초기 상태에서57개 상태에 도달했고, 목표에서 역탐색한 결과57개 모두 목표로 이어졌다. 최단 경로는25개의 매크로 행동이다. 이는 걸음 수·버튼 누름 수·최단 시간이 아니라 작성한 그래프 간선 수다. A 조작·B 조작·세계 전환을 각각 금지하면 이 그래프에서 해법이 없다는 검사도 수행한다.

**모든 연속 좌표·모든 공중 전환을 완전 탐색한 증명은 아니다.** 작성한 안전 지점과 링크에 대한 보수적인 모델이다. 낙하 후 다른 발판 착지·피트 추락·정밀 점프를 통한 미등록 지름길까지 포함하지 않는다. R/추락 복귀는 가능하지만 그래프의 역방향 복구 검사에는 재시작 간선을 넣지 않았다. 몬스터 시간·순찰 위상은 포함하지 않았으므로 나중에 적을 추가하면 이 검증을 그대로 안전성 증거로 쓰지 않는다. 충분히 생각하면 모든 사람이 풀 수 있다거나 재미있다는 보장도 아니다.

Tiled에서 지형·시작점·출구·조작점·노드·링크를 바꾼 뒤 solver를 재실행하고 실제 입력 재생 검사까지 다시 수행한다. 저장된 해법의 맵 해시가 다르면 자동 검사와 SDL 검사가 실패한다. 에디터의 BRIDGE 원본은 두 다리를 모두 포함하며 B 제외 영역은 실행 시 적용된다.

## 확인한 항목과 남은 항목

자동 검사85개: 기존 기능 회귀,맵 해시·저장 해법 일치,도달/복구 상태,필수 조작,실제 게임 입력 경로의30/60FPS 일치,물리 갱신 없는 프레임의 재생 대기,Stage2→3·재시작을 확인했다. 실제 SDL 키 입력으로 BFS 경로를 순간 이동 없이 클리어·현실 포털·R 초기화하고 낙하0회를 확인했다. Tiled CLI JSON 내보내기·렌더링을 확인했다. 이 검증은 프로그램 입력이며 사람이 직접 조작한 것이 아니다.

Tiled GUI 직접 편집,사람의 시야·규칙 이해·해법 발견·재미·난도,몬스터가 추가된 동적 안전성은 미확인이다. 다음은 처음 보는 플레이어에게 설명 없이 해법을 찾게 하여 막힌 지점과 추론 과정을 기록하는 일이다.

근거: [Amit Patel, Red Blob Games의 그래프 탐색 설명](https://www.redblobgames.com/pathfinding/a-star/introduction.html)은 위치뿐 아니라 상태와 행동으로 그래프를 구성할 수 있고, 탐색 알고리즘은 주어진 그래프 밖의 공간 의미를 알지 못함을 설명한다. 안전 지점·A/B·세계 상태 모델과 실제 물리 간선 검사·역방향 복구 검사는 이 프로젝트의 설계 선택이다.

## 레버 에셋 배치 — 2026-11-07

사용자 요청에 따라 기존 오른쪽 정비실 후보의 공통 지면에 레버를 정적으로 배치했다. [공유 lever.tsj](../tilesets/lever.tsj)의 첫 타일(원본 손잡이 왼쪽)을 사용하며 TMJ firstgid=64다. 타일 오브젝트 Service lever는 좌하단(332,247),표시32×16이고 실제 받침 기준점은(344,247)이다. 원본64×32 셀은 그대로 두고 Tiled 오브젝트만0.5배로 표시한다. 정수3배 카메라에서 표시 셀은96×48화면px다. 기존 A 조작점(360,247)과 범위를 겹치지 않게 두었다.

Objects의 ServiceLever는 kind=Lever, state=inactive, interactionEnabled=false, status=placement_only인 위치 기록이다. 현실·그림자에서 같은 자리의 장식으로 보이며 고체·조작 트리거는 추가하지 않았다. 레버 애니메이션·E 상호작용·문 연결·최근 제안한 두 조명/정비로 재설계는 이번에 구현하지 않았다. 레버 배치가 해당 재설계안 전체의 승인이나 동작 완료를 뜻하지 않는다.

추가 에셋의 상대경로·타일 사각형·표시 크기·기준점·조작점 분리를 확인했다. 맵 해시가 바뀌어 solution.json을 재생성했으며 기존57개 도달/복구 상태·25매크로 해법은 동일하다. 기존 도시·레버 PNG는 변경하지 않았다. Tiled CLI 내보내기·렌더링, 자동 검사85개와 실제 SDL 화면의 정적 배치를 확인했다. 마지막 단독 SDL 전체 재생은902프레임으로 클리어·낙하0회·재시작을 통과했다. 사람이 직접 조작한 레버 기능 검증은 해당 기능이 아직 없으므로 수행할 수 없다.

검사 주의: 앞선 SDL 전체 입력 재생2회는 경로 중간에 실패했고, 입력 상태 기록을 추가한 실행과 마지막 원래 명령의 단독 실행은 통과했다. 간헐적 재생 실패의 원인은 확정하지 않았으며 레버 배치 때문이 아니라고 단정하지 않는다. 고정30/60FPS 자동 검사85개는 통과했지만 실제 렌더 간격·포커스 등 다양한 조건의 재생 안정성은 추가 확인이 필요하다.
