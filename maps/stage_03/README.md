# Stage 3: 옥상 정비구역

기본 실행은 [옥상 정비구역](stage3_rooftop_works.tmj)으로 진입한다. 2304×960px, 8px 타일 288×120칸이다. 하층부터 네 높이를 오가며 시작점보다 768px 위의 현실 포털로 간다. 계단 중간 공통 발판에서 전환해 세계별 계단을 잇고, 벌어진 계단을 짧게 점프한다. 두 구역에서 현실 옥상으로 올라 혼합 세계 다리를 건너뛰고 주 경로에 합류할 수 있다.

`python main.py --stage 3`로 실행한다. `python tools/solve_stage3.py --map maps/stage_03/stage3_rooftop_works.tmj`로 안전 지점 그래프를 검증한다.

## 보존한 레버·가로등 원형

상태: Tiled 맵·레버 차단문이 연결된 퍼즐 초안. 사람의 재미·난도 검증 전이다. 걷기 모션 개선은 보류했다. 이번 작업은 두 가로등과 세계별 길의 순서를 검사하며, 동물·몬스터 순찰과 접촉 판정은 아직 없다. EncounterPlan 오브젝트는 향후 쥐→지상 임프 배치 후보일 뿐 실행되는 적이 아니다.

## 알고리즘 검증의 의미

[tools/solve_stage3.py](../../tools/solve_stage3.py)는 표준 라이브러리deque의 BFS를 사용한다. 상태는 `(안전 지점, 현실/그림자, A배치, B빛, 문 개방)`이며 이동·점프,Shift,E를 간선으로 삼는다. Objects의 PuzzleNode16개·양방향 PuzzleLink15개는 검증 후보 지점/연결이다. 연결을 적었다고 통과 가능으로 가정하지 않고 실제 game/player.py의 속도·중력·몸체·collision을 사용해 걷기·점프 출발 위치를 시험한다. 지지 바닥·몸체 내부 겹침을 검사해 안정적으로 서 있을 수 있는 상태만 노드에 포함한다.

[solution.json](solution.json)은 현재 맵 SHA256, 탐색 범위와 찾은 경로를 담는다. 현재 초기 상태에서115개 상태에 도달했고, 목표에서 역탐색한 결과115개 모두 목표로 이어졌다. 최단 경로는27개의 매크로 행동이다. 이는 걸음 수·버튼 누름 수·최단 시간이 아니라 작성한 그래프 간선 수다. A 조작·B 조작·세계 전환·레버를 각각 금지하면 이 그래프에서 해법이 없다는 검사도 수행한다.

**모든 연속 좌표·모든 공중 전환을 완전 탐색한 증명은 아니다.** 작성한 안전 지점과 링크에 대한 보수적인 모델이다. 낙하 후 다른 발판 착지·피트 추락·정밀 점프를 통한 미등록 지름길까지 포함하지 않는다. R/추락 복귀는 가능하지만 그래프의 역방향 복구 검사에는 재시작 간선을 넣지 않았다. 몬스터 시간·순찰 위상은 포함하지 않았으므로 나중에 적을 추가하면 이 검증을 그대로 안전성 증거로 쓰지 않는다. 충분히 생각하면 모든 사람이 풀 수 있다거나 재미있다는 보장도 아니다.

Tiled에서 지형·시작점·출구·조작점·노드·링크를 바꾼 뒤 solver를 재실행하고 실제 입력 재생 검사까지 다시 수행한다. 저장된 해법의 맵 해시가 다르면 자동 검사와 SDL 검사가 실패한다. 에디터의 BRIDGE 원본은 두 다리를 모두 포함하며 B 제외 영역은 실행 시 적용된다.

## 확인한 항목과 남은 항목

Tiled GUI 직접 편집,사람의 시야·규칙 이해·해법 발견·재미·난도,몬스터가 추가된 동적 안전성은 미확인이다. 다음은 처음 보는 플레이어에게 설명 없이 해법을 찾게 하여 막힌 지점과 추론 과정을 기록하는 일이다.

근거: [Amit Patel, Red Blob Games의 그래프 탐색 설명](https://www.redblobgames.com/pathfinding/a-star/introduction.html)은 위치뿐 아니라 상태와 행동으로 그래프를 구성할 수 있고, 탐색 알고리즘은 주어진 그래프 밖의 공간 의미를 알지 못함을 설명한다. 안전 지점·A/B·세계 상태 모델과 실제 물리 간선 검사·역방향 복구 검사는 이 프로젝트의 설계 선택이다.

## 레버와 상층 차단문 — 2026-11-07

공통 지면의 레버 받침은(344,247), 타일 오브젝트 Service lever의 좌하단은(332,247), 표시 크기는32×16이다. 원본64×32 셀과 PNG는 변경하지 않았다. 기존 A 조작점(360,247)과 분리했다. 가까운 조작점 하나를 골라 E를 전달하므로 레버를 눌러 A가 바뀌지 않는다.

현실에서 레버 반경6px·발 높이 오차6px 이내에 착지한 채 E를 누르면 원본 좌→위→우 자세를80ms씩 재생하며, ServiceGate가0.4초 동안40px 올라간다. 차단문은 상층 현실 귀환길의(392,127,24,40)에 있다. 기존 Outer_City_Decor_Railing 이미지를 원본24×8로5개 쌓아 철창을 표현했다. 케이블·LEVER·GATE LOCKED/OPENING/OPEN·문틀로 연결과 상태를 보여준다. 새 문 PNG를 만들거나 다른 팩의 문을 추출하지 않았다.

닫힌 문은 양쪽 세계에서 동일하게 막는 공통 물리 장애물이다. 위로 이동하는 매 고정 갱신에서 그림과 고체를 같은 거리만큼 함께 올린다. 통로가 열리면 실제로 통과할 수 있으며, 문 상태는 세계 전환·A/B 변경·E 재입력으로 닫히지 않는다. R·추락으로 현재 스테이지를 재시작하면 레버·문·조명과 입력을 초기화하고 F3 설정은 유지한다. F3의 장식 효과 해제는 필수 문 동작을 중지시키지 않는다.

Objects의 ServiceLever는 interactionEnabled=true, targetGate=ServiceGate, spriteObject=Service lever, radius=6이다. Gate의 openSeconds=0.4, liftHeight=40, spritePrefix=Service gate bar , cableY=195를 사용한다. 다섯 타일 오브젝트가 닫힌 Gate 직사각형을 빈틈없이 덮어야 하며 메타데이터·연결·이미지 해시·막대 배치가 잘못되면 시작 검사에서 오류로 보고한다. Tiled 미리보기는 닫힌 문과 초기 레버이며 실제 전환은 게임에서 재생한다.

탐색 상태에는 문 개방 여부를 추가했다. 레버 간선은 완전히 열린 상태까지 기다린 뒤 다음 행동을 실행한다. 실제 입력 재생도 같은 완료 조건을 기다린다. 이 이진 모델은 개폐 도중의 모든 연속 물리 상태를 완전 탐색한 것이 아니다. 개폐 중 표시·충돌 동기화와 각 조작 조건은 별도 자동 검사로 확인한다.

자동 검사93개와 실제 SDL 입력으로 레버 작동·중간 자세·문 개방·상층 문 통과·클리어·R 복구를 확인했다. Tiled CLI 내보내기·렌더링도 확인했다. 사람의 조작감·가독성·다양한 저프레임 조건은 별도 평가가 필요하다. 앞선 정적 배치 작업에서 있었던 간헐적 SDL 재생 실패가 모든 조건에서 해결됐다고 주장하지 않으며, 이번 최종 입력 재생 통과와 구분한다.
