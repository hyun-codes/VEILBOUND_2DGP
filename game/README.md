# Python 게임 코드 관리

공통 게임 코드는 `game/`, 실행 진입점은 루트 `main.py`에 둔다. 스테이지별로 플레이어·카메라·충돌 코드를 복제하지 않고 맵 데이터를 교체한다. 실행 방법과 검증 환경은 [루트 README](../README.md)에 있다.

## 구현된 모듈

| 위치 | 책임 |
| --- | --- |
| 루트 `main.py` | 공통 실행 함수 호출 |
| `game/app.py` | 입력·고정 갱신·그리기 연결, 추락/R 복귀, 포커스 일시 중지 |
| `game/game_world.py` | GameWorld: 깊이 순 객체 갱신·그리기, 순회 중 추가·제거 예약, 전체 초기화 |
| `game/timing.py` | FixedStepper: 60Hz 누적 시간, 프레임당 최대 5회 갱신 |
| `game/map_loader.py` | TMJ·외부 TSJ·PNG 치수 검사, 상대경로·GID 해석, 순수 맵 데이터와 고체 구성 |
| `game/map_scene.py` | 현재 미리보기 세계의 지형·장식과 시작·출구 마커 표시 |
| `game/camera.py` | 데드존·선행 시야·추적과 맵 경계 제한, 정수 3배 확대, Tiled 좌상단에서 화면 좌하단으로 좌표 변환 |
| `game/player.py` | AnimationSet·Player: 원본 JSON의 무기 없는 모션, 발 앵커·반전, 이동·점프·유예·버퍼 |
| `game/collision.py` | CollisionWorld: 세계별 고체 선택, 축별 이동과 지나친 충돌 면 보정 |
| `game/pico2d_backend.py` | 실제 pico2d 이미지·폰트·창과 SDL 입력·색조·최근접 확대 처리 |

GameWorld는 객체 목록을 관리한다. 현실/그림자라는 게임 세계 상태와는 역할이 다르다. 현재 MapScene과 Player를 순서대로 관리하며 각 타일마다 갱신 객체를 만들지 않는다.

실행 루프는 1/60초 단위로 갱신하고 렌더링과 분리한다. 과도한 지연에는 최대 5회 갱신 후 남은 완전한 스텝을 버리며 1스텝 미만의 나머지만 유지한다. 포커스 상실·복귀와 R 재시작 시 입력·누적 시간을 비운다. 추락 복귀는 고정 갱신 도중 발생하므로 시간 누적기를 콜백 안에서 초기화하지 않고 입력·플레이어·카메라를 복구한다. 종료와 예외 경로에서 객체·이미지·폰트·창을 정리한다.

## 수업 코드에서 개선한 부분과 근거

[LEC14의 game_world.py](https://github.com/hyun-codes/2DGP-2023184032/blob/main/Labs/LEC14_Game_World/game_world.py)의 객체 목록·객체별 갱신·깊이별 그리기 구조를 유지했다. 지금 규모에 ECS나 범용 엔진을 도입하지 않는다. 클래스 인스턴스마다 목록을 소유하도록 하여 실행·테스트 간 상태를 분리했다.

Robert Nystrom의 [Update Method](https://gameprogrammingpatterns.com/update-method.html)는 순회 중 객체 추가·삭제가 갱신 순서와 누락을 만들 수 있음을 설명한다. 이를 근거로 현재 순회 중 추가한 객체는 다음 순회부터 참여하고, 제거된 객체는 그 순회에서 차례가 남아 있어도 갱신하지 않게 했다. 실제 목록 변경은 순회가 끝날 때 적용한다. 이 정책은 나중에 사망·재시작에서 객체가 바뀔 때 사용할 수 있으며 관련 검사를 두었다. 사망 자체를 구현한 것은 아니다.

Glenn Fiedler의 [Fix Your Timestep!](https://gafferongames.com/post/fix_your_timestep/)를 근거로 고정 간격과 누적 시간 제한을 적용했다. 60Hz·최대 5회는 프로젝트 선택값이다. 저성능 환경에서 과부하가 계속되면 게임 진행 시간이 느려질 수 있다. 같은 물리 입력을 30/60 FPS로 재생한 위치·속도·착지 상태가 일치하는지 검사했다. 사람의 조작감 평가는 별도로 남아 있다.

## 데이터와 표시의 경계

- 로더와 카메라는 SDL 창 없이 검사할 수 있다. pico2d는 실제 실행을 시작할 때 불러온다.
- 파일 경로는 코드·TMJ·TSJ를 선언한 파일 기준으로 해석한다. 실행 터미널의 현재 폴더에 의존하지 않는다.
- 지도는 논리 320×240, 타일은 8×8을 유지한다. 현재 실행 확대율은 app.py의 3배이며 TMJ에 남은 과거 2배·여백 메타데이터는 사용하지 않는다.
- 그룹 오프셋, 이미지 레이어의 반복, 타일 오브젝트의 아래쪽 기준점과 레이어 색조를 반영한다. ShadowOnly의 숨김은 Tiled 초기 표시 설정이며 그림자 미리보기에서는 해당 레이어를 표시한다.
- 현재 로더는 유한 직교 맵·배열 타일 데이터·외부 TSJ와 이 맵이 사용하는 이미지/오브젝트 레이어를 지원한다. 회전·뒤집힌 GID, 애니메이션 타일, 패럴랙스 등 미지원 형식은 오류로 중단한다. Tiled의 모든 기능을 지원하는 범용 로더가 아니다.
- solid=true인 타일 레이어만 고체를 만든다. TSJ 타일의 collisionTop=7은 위쪽 투명 7px를 제외한다. 그룹 오프셋은 그림과 고체에 함께 적용한다. 현재 지면은 옆면·천장도 막으며 단방향 발판은 없다. 시작점은 플레이어 발 좌표로 사용하고 출구는 아직 트리거 없이 마커로만 표시한다.
- --world는 시작 시 고른 고정 세계이며 지형 표시와 고체를 같은 값으로 선택한다. Shift 전환이나 전환 순간의 충돌·속도 보존 규칙은 다음 구현 대상이다.

자동 검사 36개는 루트 tests/에 있다. 실제 창 검사는 native_movement_check.py를 명시적으로 실행한다. 객체 순회 중 변경, 시간 누적·지연, 카메라 경계·좌표, 실제 맵 로딩·오류, 입력·포커스·종료 경로를 검사한다. 실제 창 렌더링과 사람이 수행하는 플레이 검증은 구분한다. 기능 검증이 끝나면 [작업 규칙](../AGENTS.md)에 따라 한국어로 커밋하고 push한다.


## 이동 기반의 선택과 제한

발 앵커는 animations.json의 (32,44)를 유지하고 몸체 충돌체는 별도 6×14px다. 기본 활성 모션 5개만 읽고 무장·선택 모션은 재생하지 않는다. 물리 상태가 모션을 선택하며 착지 모션이 이동·점프 입력을 막지 않는다. 모션 시간은 고정 갱신의 활성 게임 시간으로 누적하며 과부하 시 물리와 함께 느려질 수 있다. 사망 연출의 실시간 정책은 별도 구현 대상이다.

[Maddy Thorson의 Celeste & Forgiveness](https://www.maddymakesgames.com/articles/celeste_and_forgiveness/index.html)를 근거로 가장자리 이탈 유예·착지 직전 입력 버퍼를 적용했다. 0.08초·0.10초는 프로젝트 시험값이다. 같은 높이에서의 현재 점프 높이는 고정 스텝 기준 약 21px이며 속도·몸체·유예를 포함해 현실의 64px 틈을 우회하지 못하는지 검사했다. 이 검사는 현재 물리와 맵에 한정하며 모든 미래 퍼즐의 검증을 대신하지 않는다.

[Itay Keren의 Scroll Back](https://gamedesignskills.com/game-design/camera-design-2d-side-scroller-games/)의 카메라 창과 선행 시야 설명을 참고해 중앙 가로 40% 데드존, 최대 월드 16px 선행량, 시간 기반 평활화를 구현했다. 세로 창은 20~85%로 시험하며 평소 점프는 화면을 위아래로 움직이지 않는다. 정수 화면 좌표와 맵 경계를 유지하고 화면 밖 추락까지 카메라가 따라가지 않게 한다. 수치의 최적성을 주장하지 않으며 감각·가독성은 직접 플레이로 확인해야 한다.

충돌은 고정 스텝에서 X 이동 후 Y 이동을 처리한다. 지나친 면을 검사해 빠른 수직 낙하에서도 바닥을 건너뛰지 않도록 한다. 경사면·이동 발판·회전·초기 고체 겹침 해소는 지원하지 않는다. 현재 모듈을 범용 물리 엔진으로 취급하지 않는다. 화면 밖 추락은 최종 사망 연출이 준비되기 전의 즉시 복귀 처리다.
