# Python 게임 코드 관리

공통 게임 코드는 `game/`, 실행 진입점은 루트 `main.py`에 둔다. 스테이지별로 플레이어·카메라·충돌 코드를 복제하지 않고 맵 데이터를 교체한다. 실행 방법과 검증 환경은 [루트 README](../README.md)에 있다.

## 구현된 모듈

| 위치 | 책임 |
| --- | --- |
| 루트 `main.py` | 공통 실행 함수 호출 |
| `game/app.py` | 입력·고정 갱신·그리기 연결, 추락/R 복귀, 포커스 일시 중지 |
| `game/game_world.py` | GameWorld: 깊이 순 객체 갱신·그리기, 순회 중 추가·제거 예약, 전체 초기화 |
| `game/timing.py` | FixedStepper: 60Hz 누적 시간, 프레임당 최대 5회 갱신 |
| `game/map_loader.py` | TMJ·외부 TSJ·PNG 치수 검사, 상대경로·GID 해석, 순수 맵 데이터와 고체 구성 |
| `game/map_scene.py` | 현재 세계의 지형·장식·상시 출구 안내와 디버그 시작점 표시 |
| `game/camera.py` | 데드존·선행 시야·추적과 맵 경계 제한, 정수 3배 확대, Tiled 좌상단에서 화면 좌하단으로 좌표 변환 |
| `game/player.py` | AnimationSet·Player: 원본 JSON의 무기 없는 모션, 발 앵커·반전, 이동·점프·유예·버퍼 |
| `game/collision.py` | CollisionWorld: 세계별 고체 선택, 축별 이동과 지나친 충돌 면 보정, 몸체 내부 겹침 검사 |
| `game/world_effects.py` | 표시 전용 세계 색 전환·배경 띠 물결·안개 흐름·램프 팔레트·동작 줄이기 상태 |
| `game/world_state.py` | WorldState: 현실/그림자와 충돌 집합, 전환 가능 여부·기존 지면의 점프 권한 처리 |
| `game/pico2d_backend.py` | 실제 pico2d 이미지·폰트·창과 SDL 입력·색조·최근접 확대 처리 |

GameWorld는 객체 목록을 관리한다. 현실/그림자라는 게임 세계 상태와는 역할이 다르다. 현재 MapScene과 Player를 순서대로 관리하며 각 타일마다 갱신 객체를 만들지 않는다.

실행 루프는 1/60초 단위로 갱신하고 렌더링과 분리한다. 과도한 지연에는 최대 5회 갱신 후 남은 완전한 스텝을 버리며 1스텝 미만의 나머지만 유지한다. 포커스 상실·복귀와 R 재시작 시 입력·누적 시간을 비운다. 추락 복귀는 고정 갱신 도중 발생하므로 시간 누적기를 콜백 안에서 초기화하지 않고 입력·플레이어·카메라를 복구한다. 종료와 예외 경로에서 객체·이미지·폰트·창을 정리한다.

## 수업 코드에서 개선한 부분과 근거

[LEC14의 game_world.py](https://github.com/hyun-codes/2DGP-2023184032/blob/main/Labs/LEC14_Game_World/game_world.py)의 객체 목록·객체별 갱신·깊이별 그리기 구조를 유지했다. 지금 규모에 ECS나 범용 엔진을 도입하지 않는다. 클래스 인스턴스마다 목록을 소유하도록 하여 실행·테스트 간 상태를 분리했다.

Robert Nystrom의 [Update Method](https://gameprogrammingpatterns.com/update-method.html)는 순회 중 객체 추가·삭제가 갱신 순서와 누락을 만들 수 있음을 설명한다. 이를 근거로 현재 순회 중 추가한 객체는 다음 순회부터 참여하고, 제거된 객체는 그 순회에서 차례가 남아 있어도 갱신하지 않게 했다. 실제 목록 변경은 순회가 끝날 때 적용한다. 이 정책은 나중에 사망·재시작에서 객체가 바뀔 때 사용할 수 있으며 관련 검사를 두었다. 사망 자체를 구현한 것은 아니다.

Glenn Fiedler의 [Fix Your Timestep!](https://gafferongames.com/post/fix_your_timestep/)를 근거로 고정 간격과 누적 시간 제한을 적용했다. 60Hz·최대 5회는 프로젝트 선택값이다. 저성능 환경에서 과부하가 계속되면 게임 진행 시간이 느려질 수 있다. 같은 물리 입력을 30/60 FPS로 재생한 위치·속도·착지 상태가 일치하는지 검사했다. 사람의 조작감 평가는 별도로 남아 있다.

## 데이터와 표시의 경계

- 로더와 카메라는 SDL 창 없이 검사할 수 있다. pico2d는 실제 실행을 시작할 때 불러온다.
- 파일 경로는 코드·TMJ·TSJ를 선언한 파일 기준으로 해석한다. 실행 터미널의 현재 폴더에 의존하지 않는다.
- 지도는 논리 320×240, 타일은 8×8을 유지한다. 현재 실행 확대율은 app.py의 3배이며 TMJ에 남은 과거 2배·여백 메타데이터는 사용하지 않는다.
- 그룹 오프셋, 이미지 레이어의 반복, 타일 오브젝트의 아래쪽 기준점과 레이어 색조를 반영한다. ShadowOnly의 숨김은 Tiled 초기 표시 설정이며 그림자 미리보기에서는 해당 레이어를 표시한다.
- 현재 로더는 유한 직교 맵·배열 타일 데이터·외부 TSJ와 이 맵이 사용하는 이미지/오브젝트 레이어를 지원한다. 회전·뒤집힌 GID, 애니메이션 타일, 패럴랙스 등 미지원 형식은 오류로 중단한다. Tiled의 모든 기능을 지원하는 범용 로더가 아니다.
- solid=true인 타일 레이어만 고체를 만든다. TSJ 타일의 collisionTop=7은 위쪽 투명 7px를 제외한다. 그룹 오프셋은 그림과 고체에 함께 적용한다. 현재 지면은 옆면·천장도 막으며 단방향 발판은 없다. 시작점은 플레이어 발 좌표로 사용하고 출구 사각형은 두 세계 공통 완료 트리거로 사용한다.
- --world는 시험용 시작 세계만 선택한다. Shift 전환은 고정 갱신 시작에 처리하고 지형 표시와 고체를 함께 변경한다. 위치·속도는 보존하며 R·추락 복귀는 항상 현실로 초기화한다.

## 이동 기반의 선택과 제한

발 앵커는 animations.json의 (32,44)를 유지하고 몸체 충돌체는 별도 6×14px다. 기본 활성 모션 5개만 읽고 무장·선택 모션은 재생하지 않는다. 물리 상태가 모션을 선택하며 착지 모션이 이동·점프 입력을 막지 않는다. 모션 시간은 고정 갱신의 활성 게임 시간으로 누적하며 과부하 시 물리와 함께 느려질 수 있다. 사망 연출의 실시간 정책은 별도 구현 대상이다.

[Maddy Thorson의 Celeste & Forgiveness](https://www.maddymakesgames.com/articles/celeste_and_forgiveness/index.html)를 근거로 가장자리 이탈 유예·착지 직전 입력 버퍼를 적용했다. 0.08초·0.10초는 프로젝트 시험값이다. 같은 높이에서의 현재 최대 점프 높이는 고정 스텝 기준 약 26.8px이며 속도·몸체·유예를 포함해 현실의 64px 틈을 우회하지 못하는지 검사했다. 이 검사는 현재 물리와 맵에 한정하며 모든 미래 퍼즐의 검증을 대신하지 않는다.

[Itay Keren의 Scroll Back](https://gamedesignskills.com/game-design/camera-design-2d-side-scroller-games/)의 카메라 창과 선행 시야 설명을 참고해 중앙 가로 40% 데드존, 최대 월드 16px 선행량, 시간 기반 평활화를 구현했다. 세로 창은 20~85%로 시험하며 평소 점프는 화면을 위아래로 움직이지 않는다. 정수 화면 좌표와 맵 경계를 유지하고 화면 밖 추락까지 카메라가 따라가지 않게 한다. 수치의 최적성을 주장하지 않으며 감각·가독성은 직접 플레이로 확인해야 한다.

충돌은 고정 스텝에서 X 이동 후 Y 이동을 처리한다. 지나친 면을 검사해 빠른 수직 낙하에서도 바닥을 건너뛰지 않도록 한다. 경사면·이동 발판·회전·초기 고체 겹침 해소는 지원하지 않는다. 현재 모듈을 범용 물리 엔진으로 취급하지 않는다. 화면 밖 추락은 최종 사망 연출이 준비되기 전의 즉시 복귀 처리다.


## 가변 높이 점프와 낙하 조정

[닌텐도 Super Mario Bros. 공식 설명서](https://www.nintendo.co.jp/clv/manuals/en/pdf/CLV-P-NAAAE.pdf)는 점프 버튼을 누르는 시간에 따라 높이가 달라지는 조작을 설명한다. 이 조작 원리를 참고해 Space 유지 여부를 별도로 보관하고 상승 중 놓으면 속도를 최대 -130px/s로 제한한다. 실제 원작 코드나 수치를 그대로 옮긴 것은 아니다. 순간 입력도 저장된 점프를 없애지 않으며 이미 줄어든 상승 속도는 다시 눌러도 복구하지 않는다. 공중 추가 점프도 없다. 버퍼에 넣은 뒤 버튼을 놓고 착지하면 낮은 점프로 연결된다.

Kyle Pittman의 GDC 2016 [Building a Better Jump 공식 소개](https://gdcvault.com/play/1023559/Math-for-Game-Programmers-Building)는 입력에 따른 높이 변화와 정점 이후 빠른 낙하를 다룬다. 이를 참고해 상승 중력 1000px/s², 낙하 중력 1600px/s², 점프 초기 속도 240px/s를 시험한다. 최대 낙하 속도는 기존 360px/s다. 정상적인 긴 점프는 약 26.8px 높이와 0.43초 체공을 보이며, 상승 약 0.23초·낙하 약 0.20초다. 같은 높이 지면, 현재 60Hz 적분 기준 측정값이며 단순 공식의 연속 궤적 수치와는 다르다.

높이·체공이 바뀌면 퍼즐 도달 거리도 바뀌므로 기존 현실 다리 우회·충돌·재시작 검사와 30/60 FPS 입력 재생을 다시 통과해야 한다. 버튼 해제 시점별 높이, 낙하 중 해제 무영향, 재누름 상승 복구 금지, 포커스 시 유지 상태 정리도 검사한다. 원본 모션·수평 속도·카메라 수치는 이번 조정에서 유지했다. 낙하가 너무 급하게 느껴지거나 작은 발판 조작이 어려워질 가능성은 직접 플레이에서 확인한다.


## 세계 전환과 완료 상태

app.py가 고정 스텝 시작에 예약된 Shift 누름을 소비한다. 좌/우 Shift는 개별 키 상태를 추적하되 두 키가 모두 해제되어야 새 누름으로 인정한다. 물리 갱신이 없는 렌더 프레임에서 들어온 입력은 잃지 않고, 빠르게 여러 번 눌렀다 놓은 경우에도 각 누름을 한 번씩 소비한다. 키 반복·포커스 복귀·R 재시작으로 의도하지 않은 전환이 남지 않게 한다.

WorldState.try_toggle은 대상 고체와 몸체의 엄격한 AABB 내부 겹침을 먼저 검사한다. 면 접촉은 허용한다. 거부 시 세계·위치·속도·충돌 참조를 바꾸지 않고 짧은 안내만 표시하며 다음 스텝에서 자동 재시도하지 않는다. 성공하면 위치·속도와 점프 유지/버퍼를 유지한다. 이전 지면 좌표 last_support를 기록해 해당 지면이 사라진 경우에만 남은 coyote time을 취소한다. 공통 지면의 일반 유예는 유지하고 새 공중 점프 권한은 만들지 않는다. 이 거부 정책은 PRD의 프로젝트 설계이며 외부 자료의 유일한 정답으로 주장하지 않는다.

처리 순서는 전환 검사·반영 → 객체 이동·충돌 → 화면 밖 추락 판정·복귀 → 출구 접촉이다. 현재 Stage 1에는 적이 없으므로 몬스터 위험 판정은 아직 없다. 완료는 completed 상태 한 곳에서 관리하고 이후 물리 갱신을 중단한다. 입력·버퍼를 비우고 R·Esc·F1·포커스 처리만 받는다. 화면은 계속 그리며 창 종료에 응답한다. Stage 2 데이터가 없으므로 목적지 문자열을 파일 경로로 추정하지 않는다.

현재 app.py가 Stage 1의 재시작·완료를 연결한다. 실제 다중 스테이지가 생길 때 stage_manager.py로 분리하며 빈 관리자를 미리 만들지 않는다. 사망 모션·화면 흔들림·동물 위험 처리와 사람의 플레이 평가는 남아 있다.


## 전환 연출과 가독성

WorldEffects는 활성 상태의 실제 경과 시간을 렌더 프레임마다 받는다. 물리 따라잡기 횟수와 별개로 0.2초 동안 배경 색을 부드럽게 바꾸며 전환 시 짧은 세계 이름 표시도 제공한다. 연타하면 현재 보이는 색에서 새 목표 색으로 이어가며 물결을 누적하지 않는다. 전환 거부에는 성공 표시를 취소하고, 재시작은 현실의 정적 초기 표시로 돌아간다. 포커스 상실 동안 연출 시간도 멈춘다. 완료 후 색 전환은 마무리하되 배경·안개 시간은 멈춘다.

맵 로더는 이미지 레이어를 background, Low fog 레이어를 fog로 분류한다. 이미지 레이어의 visualRole 속성으로 지정할 수도 있다. 타일 지형은 terrain이며 원본 소품 TSJ의 램프에 visualRole=lamp를 지정했다. 플레이어는 기본 none으로 물결·색조를 적용하지 않는다. 지면은 현재 세계의 표시·색으로 즉시 바꾸며 과거 발판의 잔상을 겹쳐 그리지 않는다.

배경 이미지를 원본 높이 8px의 가로 띠로 나누어 원본 픽셀 정수 단위로 좌우 변위시킨다. 화면 변위는 보통 3px이며 빠른 재전환 등에서 최대 6px 범위다. 가장자리에는 반복 하늘을 추가로 그려 빈틈을 채운다. 최근접 정수 3배 확대를 유지하고 카메라·충돌·지면·캐릭터·HUD 좌표를 바꾸지 않는다. 그림자에서는 약한 원경 물결을 지속한다. 기존 반복 안개 이미지는 현실 +2px/s, 그림자 -3px/s를 기준으로 흐르며 색 전환 중 속도를 연결한다. F3을 끄면 물결을 제거하고 안개를 그 위치에 멈추되 색·세계 표시와 조작은 유지한다. 설정은 재시작 후에도 보존한다.

원본 램프의 황색 (255,240,137)과 흰색 두 밝은 색만 SDL 메모리 표면에서 청보라색으로 교체한다. 어두운 기둥·투명도와 원본 PNG는 보존한다. 원본/그림자 텍스처는 각각 한 번 로드해 캐시하고 종료 시 함께 정리한다. 새 이미지나 외부 렌더링 도구·의존성은 추가하지 않았다. 픽셀별 변환은 로드 시 램프에만 수행하며 매 프레임 배경 전체를 CPU로 변환하지 않는다.

근거: [Guacamelee 개발자 인터뷰](https://blog.playstation.com/archive/2017/11/06/extended-play-how-guacamelee-went-from-design-pitch-to-indie-sensation/)는 두 세계의 서로 다른 색상 팔레트와 장식 변경을 설명한다. [Giana Sisters 공식 Steam 설명](https://store.steampowered.com/app/223220/Giana_Sisters_Twisted_Dreams/)은 세계 변형과 세계별 음악 교차 전환을 설명한다. 물결 구현과 시간·강도는 VEILBOUND의 시험안이며 두 작품의 원본 구현을 복제한 것이 아니다. F3 옵션은 [Xbox 접근성 지침 117](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117)의 화면 움직임 효과 조절 취지를 반영한다.

assets/에서 사용 가능한 음원을 확인하지 못해 음악·효과음 전환은 미구현이다. 가로등 이동과 그림자 지형의 인과 퍼즐도 다음 기능으로 남긴다. 현재 변경은 세계 전환의 시각 인지 개선이다. 효과 강도의 편안함과 다른 PC에서의 성능은 직접 평가가 필요하다.
