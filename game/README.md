# Python 게임 코드 관리

실제 게임 코드는 이 `game/` 폴더에서 관리한다. 스테이지가 바뀌어도 같은 플레이어·카메라·세계 전환·충돌 코드를 사용하고 `maps/`의 배치 데이터만 바꾼다. `stage_01/player.py`, `stage_02/player.py`처럼 코드를 스테이지별로 복제하지 않는다.

## 실행 진입점과 모듈

Python 공식 문서는 프로그램이 커지면 여러 모듈로 나누고 필요한 정의를 import하여 재사용하는 방식을 설명한다. 이 프로젝트의 `main.py` + `game/` 배치는 그 원리를 적용한 관리 방식이며, Python이나 pico2d가 강제하는 유일한 구조는 아니다.

| 위치 | 앞으로 구현할 책임 | 추가 시점 |
| --- | --- | --- |
| 루트 `main.py` | 프로그램 실행 진입점, 공통 게임 코드의 시작·종료 연결 | 첫 실행 기능 |
| `game/app.py` | 이벤트 처리·고정 간격 갱신·그리기를 연결하는 실행 흐름 | 첫 실행 기능 |
| `game/map_loader.py` | TMJ·TSJ 읽기, 파일 기준 상대경로 해석, 맵 데이터 구성 | 맵 출력 |
| `game/player.py` | 이동·점프·입력 유예·플레이어 상태 | 이동 기반 |
| `game/collision.py` | 활성 지형과 플레이어·동물의 충돌 계산 | 착지·충돌 |
| `game/camera.py` | 추적·경계·월드에서 화면으로의 변환·화면 흔들림 | 카메라 |
| `game/world.py` | 현실/그림자 선택과 전환 가능 여부 | 세계 전환 |
| `game/stage_manager.py` | 스테이지 목록, 진입·재시작·완료 흐름 | 스테이지 진행 |
| `game/animal.py` | 동물 순찰과 세계에 따른 외형·접촉 위험 | 동물 구현 |
| `game/settings.py` | 화면 크기·조정값·공용 경로 등 설정 | 실제 공통 설정이 필요할 때 |

이 표는 계획이다. 현재 위 Python 파일은 생성하지 않았다. 각 기능을 구현할 때 필요한 파일과 `game/__init__.py`를 추가한다. 작은 상태·함수까지 모두 파일로 쪼개거나, 빈 클래스·범용 엔진·ECS·플러그인 구조를 미리 만들지 않는다. 역할이 커지면 실제 의존관계에 맞춰 모듈을 조정한다.

## 파일·데이터를 나누는 기준

- `.py`는 동작을 정의하고, `.tmj`는 지형·시작점·출구·동물 배치를 정의한다.
- 스테이지별 차이는 우선 맵 데이터와 속성으로 표현한다. Stage 1의 좌표를 공통 플레이어 코드에 박아 넣지 않는다.
- 물리·세계 상태는 렌더링 배율과 카메라 이동에서 분리한다. 그리기용 좌표를 다음 충돌 계산에 되먹이지 않는다.
- 파일 경로는 실행한 터미널의 현재 폴더에만 의존하지 않게 한다. 프로젝트 루트는 코드 파일 기준으로 찾고, TSJ·이미지 참조는 그것을 선언한 파일 기준으로 해석한다.
- `app.py`는 필요한 모듈을 연결한다. 하위 모듈이 `main.py`를 import하거나 불필요한 순환 import를 만들지 않는다.
- 구현 코드의 검증이 필요해지면 루트 `tests/`에 관련 검사를 둔다. 수동 플레이 확인과 자동 검사를 구별해서 기록한다. 지금은 빈 테스트 파일을 생성하지 않는다.
- Python·pico2d 실행 환경과 설치 항목은 첫 실행을 검증한 뒤 기록한다. 추측한 버전이나 미확인 실행 명령을 완료된 설정으로 남기지 않는다.
