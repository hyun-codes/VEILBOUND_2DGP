# 점프 입력·해제 제동 개선

## 확인한 문제

60Hz에서 평평한 바닥으로 측정했다. 기존 구현은 Space 해제 시 상승 속도를 즉시 -110으로 바꿨다. 첫 물리 갱신 전에 버튼을 놓으면 높이가 5.40픽셀, 한 갱신 유지 후 놓으면 9.10픽셀, 계속 유지하면 27.53픽셀이었다. 해제 순간 속도 변화가 크고 짧은 입력의 높이가 매우 낮다는 재현 가능한 문제다. 이것이 모든 불편의 원인이라는 사용자 실험 결과는 아니다.

착지 직전 저장한 점프도 착지 다음 물리 프레임에 시작했다. 기존 자동 클리어 검사는 유지 입력을 생략하면 최대 높이로 실행하므로, 짧게 누르는 사람의 불편을 충분히 검사하지 못했다.

## 조사 근거와 설계 판단

- Fasterholdt, Pichlmair, Holmgård (2016), [You Say Jump, I Say How High?](https://dl.digra.org/index.php/dl/article/download/771/771), 특히 pp.10–12: 최소 점프 시간, 버튼 해제에 따른 제동 방식, 입력 캐시를 서로 다른 특징으로 측정한다. Super Meat Boy의 최소 시간과 Limbo의 상승 중 하향 힘을 설명한다. **적용 판단:** 즉시 도약은 유지하고 최소 상승 시간과 해제 중력을 사용한다. 0.06초와 2400이라는 수치는 논문 권장값이 아니라 우리 맵의 높이를 보존하며 정한 값이다.
- Dahl & Kraus (2015), [공식 출판 초록](https://vbn.aau.dk/da/publications/measuring-how-game-feel-is-influenced-by-the-player-avatars-accel/), [저자 공개 선행 원고](https://gustavdahl.net/other/GameFeel_GustavDahl_Medialogy2015.pdf), 특히 원고 pp.14–15: 가감속 변화에 대한 표현과 민감도가 사람마다 다르며 문맥도 영향을 준다. **적용 판단:** 임의의 관성을 한꺼번에 추가하지 않고, 측정된 해제 제동 문제를 먼저 바꾼 뒤 사용자가 비교해야 한다.
- Normoyle, Guerrero, Jörg (2014), [Player Perception of Delays and Jitter in Character Responsiveness](https://alinen.net/research/normoyle14DelayAndJitter.pdf), 특히 pp.5–6: 실험한 플랫폼 게임에서 변동 지연이 점프 타이밍과 경험에 영향을 주었다. **적용 판단:** 착지 버퍼의 불필요한 한 프레임 대기를 없앤다. 연구의 수백 ms 지연 결과를 우리 게임의 16.7ms 개선 효과로 일반화하지 않는다.

플랫폼 게임 점프·입력 응답·가감속 체감에 직접 관련된 자료를 검색한 범위다. 모든 게임 조작 논문의 체계적 문헌고찰은 아니며, 플레이 영상 분석으로 주장하지 않는다.

## 구현과 측정

- 입력 즉시 기존 속도 -238로 도약한다. 최초 0.06초의 최소 상승 동안에도 천장 충돌은 그대로 적용한다.
- 해제 후에는 상승 중력을 960→2400으로 바꿔 제동한다. 다시 누른 것으로 상승을 복구하지 않는다. 하강 중력 1056과 최대 낙하 속도 350은 유지한다.
- 코요테 타임 0.10초, 입력 버퍼 0.12초와 빛 소멸 예외를 유지한다. 버퍼가 남아 있으면 착지 프레임에 도약을 시작한다.
- 같은 바닥에서 Space 유지 0/1/3/5/8/15프레임의 높이: 18.13/18.13/18.13/19.73/23.80/27.53 원본 픽셀. 높이는 유지 시간에 따라 단조 증가하고 최대 높이는 유지된다.
- 이전 테스트의 ‘짧은 점프와 긴 점프가 10픽셀 이상 달라야 한다’는 가정은 의도적으로 폐기했다. 대신 짧은 입력 18~23, 최대 높이 27~28과 두 높이의 분리를 검사한다. 낮은 탭 높이가 문제였으므로 기존 격차를 유지하는 것은 개선 목표와 충돌한다.

## 검증과 한계

전체 unittest 63개 통과. 짧은 입력, 속도 급변 방지, 즉시 착지 점프, 재누름, 천장 충돌, 빛 소멸과 기존 스테이지 입력 재생을 포함한다. 실제 SDL 렌더링에서 짧게/길게 누른 상태를 확인했다. Stage 9 구조 확인 화면 30회 draw+present는 해당 환경에서 평균 6.53ms, 최대 8.89ms였다. 전체 게임의 최악 프레임 시간이나 키보드부터 화면까지의 지연 측정은 아니다.

좌우 속도·수평 관성·맵·캐릭터 이미지는 변경하지 않았다. 최소 점프가 높아졌으므로 매우 낮은 궤적이 필요한 상황의 선택 폭은 줄어든다. 천장은 계속 상승을 막는다. 새로운 우회 경로의 전수 탐색과 초견 사용자 A/B 평가는 수행하지 않았다. 사용자에게는 같은 발판에서 짧게 누르기, 유지하기, 착지 직전 다시 누르기를 비교받아야 한다.
